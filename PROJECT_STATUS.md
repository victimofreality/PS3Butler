## Recovery milestone: persistence and shutdown
- QueuePersistenceCoordinator snapshots user inputs on the calling/UI thread, serializes background writes, retains only the newest pending snapshot, detaches subscriptions on collection reset/stop, and writes a final snapshot at shutdown.
- Completed/already-existing jobs are omitted; restored jobs start waiting. Corrupt queue files safely restore an empty queue. The existing JSON shape remains.
- QueueShutdownCoordinator enters stopping state, cancels pipeline/startup waits, waits for active queue commands and startup cleanup, then stops persistence.
- MainViewModel blocks queue commands while stopping, including picker results returning after shutdown starts.

## Asynchronous queue restore milestone

Saves are suppressed while restoring and after an unexpected restore failure. Stop awaits restore before taking the final snapshot, so closing during startup cannot overwrite unread inputs with an empty queue.

MainViewModel exposes queue initialization completion and IsQueueLoading. Queue controls stay locked and display Loading queue... until successful initialization. Shutdown awaits initialization and existing startup cleanup before persistence flush. Unexpected restore failures remain visible and block edits/saves; existing QueueStateService corrupt-file behavior remains a safe empty restore. MainWindow accepts an optional queue-store dependency for deterministic blocked-read UI tests; normal construction still uses the existing settings path.

All persistence callers now await StartAsync. Existing file format, fresh waiting state, terminal filtering, coalescing, save errors/retry, pipeline settings snapshots, duplicate checks and output behavior remain unchanged. Settings loading and applying the restored collection remain on the UI thread; only queue-file I/O/deserialization moved off it.

## Coalesced persistence milestone
QueuePersistenceCoordinator now keeps one active write and one replaceable pending snapshot instead of retaining a write/task/snapshot for every edit. Snapshots are still captured before background work. A single drain loop writes serially; later snapshots replace only pending work, never the active write. Stop takes a final snapshot, drains pending work, and preserves save-failure reporting/retry. Existing JSON shape, input-only persistence and terminal-job filtering are unchanged. Queue restore was subsequently made asynchronous in the milestone above.

IQueueStateStore provides the existing Load/SaveSnapshot boundary so tests can block or fail a write deterministically while the production QueueStateService continues using its existing transactional file-write implementation. The queue-save gate guards pending/writer state for background continuations; live jobs remain caller/UI-owned.
